# Round 2 changes: legally defensible orders and automation-bias safeguards (27-09-2026)
Input: `iterations/round2_critique.md` (Top 8 + all P0s). Lens: the SDO / Tehsildar who signs, and who must be able to hand the file to the High Court or vigilance.

## Result in one line
- Every issued order is a real order (no "DRAFT"), names the correct statute, the office that has territorial jurisdiction, the documents actually on file, every record shown and why it was or was not relied upon, and the officer's own satisfaction.
- Clean files still take **3 keystrokes** (Ctrl+↵ → Space to tick "I have read the order" → ↵), and the officer now sees the full order before signing.

## What changed
1. **Real orders** (P0-1, P0-2, P1-8, P1-9, P2)
   - `rules.py`: exact statute title (en/hi) plus s.4, s.5, s.15, r.3(3) (documents / relative's certificate / OBC income), r.7–8, cut-off dates, HC cause title (*Shailey Sonkar v. State of CG*, 22-07-2026; WPC no. still to verify).
   - Signing finalises the text server-side (`engine.finalise`): draft header removed; "आदेश / ORDER (English translation … Hindi authoritative)", number `SDO-KON/2026/0001` (`REF/`, `NTC/`, `SCN/` for references, notices, show-cause), date, place, "(प्रामाणिक पाठ: हिंदी)", e-sign line. Stored in `decisions`, returned as `issued_text`, fetchable via `GET …/issued`.
   - Office, place and designation come from the application: Tehsildar → the tehsil (08857 → Tehsildar, Makdi); SDO → sub-division map (Keskal / Farasgaon / Bade Rajpur / Dhanora → SDO Keskal; others → SDO Kondagaon) **[verify mapping]**. The client no longer hard-codes "Kondagaon".
   - Orders are split into *Records relied upon*, *Records considered and not relied upon (with reason)*, *Legal basis*, *Facts from the records* (system) and *Satisfaction of the undersigned* (officer). DD-MM-YYYY dates; no "(mock)"; Hindi category names in Hindi text; Hindi Form 2A reads "फॉर्म 2A" so "प्रारूप" only ever means draft; domicile affidavits are not Form 2A.
2. **Signing dialog shows the full order** (P0-3): scrollable Hindi (authoritative) / English (translation) text as it will be issued; system lines tinted yellow, the officer's own words and choices green (typed finding, recorded grounds, evidence picked, reply summary, manual edits); required "मैंने पूरा आदेश पढ़ लिया है / I have read the order" tick (autofocused; Space ticks, ↵ signs only once ticked). "Reject → Patwari" label bug fixed.
3. **Confirm relationship is a reasoned, two-sided, reversible act** (P0-4): "✓ Same family (C)" / "✗ Not this family (N)" of equal weight directly under the table; a grounds pop-over with 1-click chips (same father's name & village — pre-ticked only when both agree; family known to office; Patwari report; applicant's declaration / not-this-family chips) + optional note; ↵ records. Undo until signing (`POST …/clear-match`, audit `relationship_unconfirmed`). "Not this family" (`POST …/reject-match`) removes the record from evidence, closes its flags and re-evaluates the lane (08841 → standard review). Grounds are written into the order ("spelling variants of one name … same village (Bayanar, LGD 448703)").
4. **Show-cause before reject** (P0-5, P1-12): X on any file routes to a SHOW-CAUSE notice (15 days, adverse records listed verbatim, officer's grounds), status `show_cause_issued`; the panel then waits, with demo buttons "Reply received" (optional summary) / "No reply by due date". The final reject order lists the adverse record under *relied upon*, recites the notice number/date and the reply, cites s.4/s.15/s.5 and "appeal within 30 days … to the Appellate Authority / अपीलीय अधिकारी" (presenter mode adds "[appellate authority as notified — confirm with Revenue Dept]"). Citizen reject message: order on Sewa Setu, s.5, 30 days, no reason text / relative's caste on WhatsApp.
5. **No false statements** (P0-6, P0-7, P1-6, P1-7): checklist adds Patwari 3-generation family tree (Rule 3(3); shown, not a send-back ground — **confirm with CHiPS**) and the OBC father's income certificate (required; 08870 now has it on file, 08835/08749 ask for it). "All required documents are on file" is gone; facts say exactly what is and is not on file. Possible matches must be disposed of before approval and appear in the order with the officer's reason. A possible record whose category conflicts with the claim is an attention flag (08749). Temporary certificates: competence tested only for permanent ones; flag says "temporary — never lineage proof" (08766). New validity check "issue date not in the future / not after the application" (08721's 28-10-2026 sibling certificate fails).
6. **Decision snapshot + callback** (P1-1, P1-2): each decision/notice stores what the screen showed (model/rules version, lane, suggestion, every match with level/probability/validity/disposition, open flags, checklist, evidence basis, show-cause, system vs signed text hashes, `edited`, read tick, time on screen). Audit page: click a row for "what the screen showed"; header no longer claims an applicant view; "DPDP Rules 2025 · logs kept ≥ 1 year"; agreement kept only inside the snapshot. "Call back (10 min)" with a mandatory reason on the decided panel (and from the toast via "View order · Call back"); audit `decision_called_back`.
7. **Anti-anchoring** (P0-8, P1-11, P1-13): no pre-selected action on standard review, open flags, unconfirmed matches or after a show-cause reply; standard-review approval goes through a 2-click evidence picker ("Caste shown by ▾", "Residence before {cut-off} shown by ▾") whose choice becomes the order's finding. No-match notice: "No family record found — this is NOT a ground for rejection. Model recall is lower for married women (records under husband's village); check maiden village if applicable." Link badge shows "strong/possible link · model · 98%" with the "~1 in 10 strong links wrong on test data" tooltip; queue/evidence lines use words, not %. Lane text no longer says "verified". Provenance: "Declared by the applicant (Form 2A)" auto-accepts; "Attached by the Kendra after an archive search" (`declared_source: kendra_search`, demo 08772) needs the officer's confirmation.
8. **Carry-overs**: one-line comparison rows (5 + context), scroll-to-top on every case change, info flags moved below the card, attention flags on top; reference to the Patwari has Rule 7/8 terms of reference and a report-by date; a Patwari is not offered for competence / date questions (08863, 08721 → Committee only); cancelled certificate cites the Committee's order No./date (08856). Kendra: no hero banner, role pill "Kendra operator / केंद्र संचालक", strength word instead of %, consent tick required and logged, "attached as a Kendra search result — officer must confirm". Phone (375 px): nav collapses into the ⋯ menu, `scrollWidth ≤ 375` on /, /kendra, /officer, case pages, /collector, /audit; a fixed "Decide ↓" button jumps to the action panel (Sign button within one screen).
